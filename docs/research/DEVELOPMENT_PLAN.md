## 分层验收

P0 必须闭环：能运行正常/故障仿真并读取真实数据；检测算法与标签区分；一个明确 estimand 的因果实验；至少一种可行动作在相同历史对照中验证；导出来源和原始结果。无法通过时缩小到一个故障和一个动作，保留算法正确性。

P1：至少三种动作（含不干预）可比；根因候选和假设可查看；所有结果可追溯到运行档案；完成至少阈值、PCA、PyRCA 和简单规则的适用对照。PyRCA 若依赖阻塞，要记录原因和未完成状态，不能冒称已完成对照。

P2：工业布局、流股/仪表状态、操作反馈和可访问颜色；高级因果发现、额外设备、PDF、LLM、3D 均为可删范围。

## 风险与处理

## 首次开发前要固定的实验设置

固定种子清单和 split、预热时间、故障时刻、dt、采样频率、控制模式、动作幅值/速率、损失归一化、约束和停机惩罚。先测单次运行耗时，再决定总场景数量。阶段目标是完成可复核实验，不预设必须达到的“准确率”。

最小验收包：正常/故障/干预三组原始轨迹及 manifest；检测和根因指标；至少一组估计效应与仿真效应对比；多种子方案成本/违反率；消融表；依赖与许可；沙盘演示；一条完整复现命令。合成 API 冒烟验证不能代替 TEP 因果实验。

实施依据见 [开源调研](OPEN_SOURCE_RESEARCH.md)、[数据规范](DATA_SOURCE_ANALYSIS.md)、[核心算法方案](INNOVATION_ANALYSIS.md)。
